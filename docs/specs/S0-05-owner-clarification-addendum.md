## A. TestAttempt identity

1. Internal TestAttempt identity is UUIDv7.
2. External execution reference is nullable and non-unique.
3. NULL means no external reference was supplied to SDRIS; it does not establish that the source system has no execution
   identifier.
4. Stage is required and limited to IST and SAT for S0-05.
5. Unsupported stages must be rejected explicitly, not silently converted or mapped.
6. No authoritative PASS/FAIL result is stored.

## B. CaseTestAttemptLink identity

1. A link is identified by `(case_id, attempt_id, role)`.
2. No additional link UUID is required in S0-05.
3. The same attempt may have multiple roles in one case.
4. Identical requests are idempotent.
5. Different roles create distinct links.
6. No role is automatically inferred, modified, or removed.

## C. Transaction and concurrency contract

1. Every new link must be committed atomically with the corresponding Case Version increment.
2. A duplicate link must not increment the Case Version.
3. The service must validate Case existence, Attempt existence, and same-UUT ownership.
4. Optimistic concurrency must reject a genuinely stale new-link operation.
5. A concurrent identical request may return idempotent success only after confirming the committed link exists and matches
   the requested identity.
6. Failed PostgreSQL transactions must be rolled back before re-evaluation.
7. No unlimited retry loop.
8. Unrelated unique-constraint failures, foreign-key failures, or database errors must not be converted into idempotent
   success.
9. A failed transaction must never leave a committed link without its Case Version update, or vice versa.

## D. Timestamp contract

1. `created_at`, `registered_at`, `opened_at`, and `linked_at` represent SDRIS record events.
2. PostgreSQL generates these timestamps using `timestamptz`.
3. Store and exchange timestamps with unambiguous UTC semantics.
4. Application callers cannot arbitrarily override these timestamps in S0-05.
5. Timestamp equality is permitted; ordering must use additional deterministic keys.
6. External execution time remains separate and outside the S0-05 scope.

## E. Deterministic retrieval

Linked attempts are ordered by:

1. `registered_at ASC`
2. `attempt_id ASC`
3. Explicit role rank: INITIAL_FAILURE, RETEST, SUPPORTING, CONTEXT

The query must not rely on implicit PostgreSQL row order.

## F. Approval governance

1. Record the Engineering Owner's confirmed design direction in the Owner Decision Register.
2. Incorporate all approved decisions and clarifications into the S0-05 Specification and Persistence Policy.
3. Check for contradictions between the documents before marking the specification APPROVED WITH CHANGES.
4. ADR-025 and Amendments A1–A4 remain PROPOSED pending their separate approval.
5. Do not infer ADR approval from domain implementation authorization.
6. No PR merge or S0-06 work is authorized.

## G. Required regression tests

Include real PostgreSQL tests for:

- Two concurrent identical link requests.
- Two concurrent different-link requests against the same Case Version.
- Idempotent duplicate without version increment.
- Stale writer rejection.
- Transaction rollback after database errors.
- Cross-UUT rejection at domain and database levels.
- Timestamp generation and non-overridable creation times.
- Deterministic retrieval when timestamps are identical.
- Unsupported Stage rejection.
- Optional external execution reference.

All tests must be repeatable and deterministic.
